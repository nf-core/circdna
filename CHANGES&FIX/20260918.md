# 2026-09-18 修复记录

本轮修复来自 eccDNA 整合数据库构建过程中发现的问题，涉及 3 个长读/短读检测链和 1 个元数据错误。

---

## 1. 数据元数据错误：ERR6326020 被错标为拟南芥

**问题**：`samplesheets/metadata.csv` 把 `ERR6326020` 标为 `Arabidopsis_thaliana / Arabidopsis_ONT_eccDNA`，
但它实际出现在 `Triticum_aestivum_longread` 样本表里，两处冲突。

**核实**（ENA Portal API + NCBI dataset report）：

| 字段            | 值                                                                                  |
| --------------- | ----------------------------------------------------------------------------------- |
| run             | ERR6326020                                                                          |
| study           | PRJEB46420 / ERP130605（ecc_finder 基准数据集）                                     |
| sample          | SAMEA8987722，alias `eccDNA-seq wheat ONT rep1`                                     |
| scientific_name | **Triticum aestivum**（taxid 4565），source material `Swiss winter wheat cv. Arina` |
| platform        | OXFORD_NANOPORE MinION                                                              |
| reads / bases   | 154,105 / 430,691,964                                                               |

**结论**：样本表（小麦）正确，`metadata.csv` 错误。

**修改**：`samplesheets/metadata.csv` 中该行改为
`circdna,Wheat_ONT_eccDNA_Arina,ERR6326020,Triticum aestivum,Wheat,PRJEB46420,...`。

**影响**：ERR6326020 是**已完成**的小麦 ONT eccDNA 样本（CReSIL/FLEd/Flye/filtering 全套产出，
CReSIL 3,346 个事件），不属于“80 样本 ONT RCA 尚未跑完”的批次，因此改为纳入统计；
数据库排除规则从「小麦长读全排」改为「小麦长读中无 CReSIL 输出的（未跑完）才排除」。

## 2. CircleFinder 全样本 0 检出（严重）

**症状**：119 个短读样本的 `*.microDNA-JT.txt` 全为空文件，
`*.circle_finder_exit_log.txt` 全为 `No split reads found; no eccDNA detected.`

**排查**：`bedtools bamtobed -cigar` 输出 7 列，**CIGAR 在第 7 列**；而
`modules/local/bedtools/splitbam2bed/main.nf` 的 awk 却对**第 8 列**做 M/S/H 展开并用
`$9/$NF` 判定，第 8 列恒为空 → 判定恒不成立 → `split.txt` 为空文件。

同时该模块的 `sed -e 's/_1\/1/ 1/g'` 依赖 read name 带 `_1/1` 后缀，而 SRA 数据 read name 形如
`ERR10889838.13761231`（无后缀），因此字段数永远比 CIRCLEFINDER 的硬编码索引少 1，
下游 step8 的 `$10/$16` 全部错位。

**实测复现**（`tmp_cf_test/`，取 ERR10889838 10% 子集）：

| 链路 | split.txt    | 最终 microDNA |
| ---- | ------------ | ------------- |
| 旧   | 0 行         | 0             |
| 新   | 1,143,665 行 | **957 条**    |

**修改**：

- `modules/local/bedtools/splitbam2bed/main.nf`：直接输出 9 个空白分隔字段
  `chr start end readID readNo mapq strand cigar tag`；CIGAR 分类改为对 CIGAR 本身做
  `^[0-9]+M … [SH]$ → first`、`^[0-9]+[SH] … M$ → second`；readNo 由 name 后缀推导（无后缀记 `0`）。
- `modules/local/bedtools/sortedbam2bed/main.nf`：输出 8 列，
  **CIGAR 落到第 8 列**（CIRCLEFINDER step10 就是按 tab 第 8 列做 M/S/H 展开），
  同样显式写出 readNo 列。

> CIRCLEFINDER 模块本体（step5–step11）未改动，它要求的字段位置是硬约束，本次让上游严格对齐。

## 3. ecc_finder 中间 BED 恒为空

**症状**：所有长读数据集的
`intermediate/NFCORE_CIRCDNA/CIRCDNA/ECC_FINDER_ONT_SLIM/ECC_FINDER_ONT_CSV_TO_BED/*.bed`
只有表头。但 `ecc_finder_slim/ont/ont_merge/*.csv` 有真实结果。

**根因**：容器内 `/opt/ecc_finder_slim/bin/ont_merge.py` 的输出是
**4 列** `refID rstart rend read_count`（无表头）；而 `bin/eccfinder_ont_to_bed.py`
要求 ≥6 列（按旧版 `chr start end num_s num_d len` 写），因此每行都被 `continue` 跳过。

**修改**：`bin/eccfinder_ont_to_bed.py` 同时兼容 4 列与 6 列布局。
验证（SRR24335762）：修复前 0 条 → 修复后 **245 条**。

## 4. 长读过滤终集几乎为空

**症状**：`long_read/filtering/<sample>/*.filtered.bed` 38 个样本合计仅 56 条。

**根因（三重）**：

1. **CReSIL 未转成统一 BED**：`workflows/circdna.nf` 直接把 CReSIL 的 10 列原始表
   `eccDNA_final.txt` 喂给 `LONG_READ_FILTERING`。`filter_by_read_support.py` 识别不到支持度列
   （回退到第 5 列 `ctc`，`int("False")` 抛错后整行保留），既不真过滤也产不出 BED。
   而 `bin/convert_cresil_to_bed.py` 是**死代码，从未被任何模块引用**；且其列映射本身就是错的
   （第 1 列是 `id` 不是 chrom，第 2 列是 `merge_region` 多区段字符串）。
2. **阈值过严**：`min_read_support = 2`，而 FLEd junction 的支持数**全部为 1**
   （15 个拟南芥样本 124,268 条 junction，read_count 分布只有 `1`）→ 被整批滤掉。
3. **发布名冲突**：多个引擎都把结果写成 `<sample>.filtered.bed` 并发布到同一目录
   `long_read/filtering/<sample>/`，互相覆盖。

**修改**：

- `bin/convert_cresil_to_bed.py`：按真实列定义重写（`id / merge_region / ... / numreads`），
  取 `merge_region` 首个区段作为代表位点，`read_count = numreads`，name 保留事件 id 与区段数。
  验证（SRR24335762）：4,386 个事件全部正确转换。
- 新增 `modules/local/cresil_to_bed/`（main.nf + environment.yml），并在
  `workflows/circdna.nf` 中把 CReSIL 原始表先经 `CRESIL_TO_BED` 转成统一 BED 再进过滤。
- `nextflow.config`：`min_read_support` 默认 2 → **1**（长读单条 read 跨越接点即为有效证据）。
- `modules/local/filter_eccdna_by_support/main.nf`：输出名改用 `task.ext.prefix`；
  `conf/modules.config` 为 6 个长读引擎实例分别设置前缀（`.cresil/.fled/.flye/.circleseeker/.eccfinder/.eccfinder_asm`），
  消除覆盖。
- `conf/modules.config`：新增 `CRESIL_TO_BED` 发布规则。
