# 2026-07-24 修改记录

## 概述

本次修改主要完成 Phase 0 Bug 修复和 ecc_finder 第四引擎集成，使长读 eccDNA 分析流程基础稳定性达到可运行状态。版本从 v3.1.0 升级到 v3.2.0。

## 修改清单

### 1. Phase 0 Bug 修复

#### Bug 1: FLED_PIPELINE 输入不匹配

- **文件**: `subworkflows/local/long_read_mapping/main.nf`
- **问题**: `LONG_READ_MAPPING` emit 为 2 元组 `[val(meta), sorted.bam]`（无 bai），但 `FLED_PIPELINE` 的 `take` 声明为 3 元组 `[val(meta), bam, bai]`
- **修复**:
  - 在 `LONG_READ_MAPPING` 中新增 `SAMTOOLS_INDEX` 调用生成 bai
  - 通过 `sorted_bam.join(bam_index, by: [0])` 合并为 3 元组
  - `FLED_PIPELINE` 的 `take` 保持 3 元组不变

#### Bug 2: FLED_PIPELINE channel.value() 误用

- **文件**: `subworkflows/local/fled_pipeline/main.nf`
- **问题**: `channel.value(genome_fasta)` 中 `genome_fasta` 是 channel 而非值，导致 `Argument 2-nd of method 'channel.value' cannot be a channel object` 错误
- **修复**: 改用 `mapped_reads.combine(genome_fasta)` 将参考基因组合并到输入 channel

#### Bug 3: LONG_READ_PREPROCESSING emit 缺失

- **文件**: `subworkflows/local/long_read_preprocessing/main.nf`
- **问题**:
  - `preprocessed_fastq` 在 `if` 块内用 `def` 声明，emit 时无法访问
  - `nanoplot_qc` 和 `versions` 的 emit 名称与变量名不匹配
- **修复**:
  - 移除 `def` 关键字，使变量提升为 workflow 作用域
  - 使用 `emit: preprocessed_fastq = preprocessed_fastq` 语法显式绑定

#### Bug 4: LONG_READ_FILTERING 重复调用

- **文件**: `workflows/circdna.nf`
- **问题**: `LONG_READ_FILTERING` 被 CReSIL 和 FLED 分支分别调用，DSL2 中同名组件不能重复使用
- **修复**: 使用 `as` 别名引入两次：
  ```groovy
  include { LONG_READ_FILTERING as LONG_READ_FILTERING_CRESIL } from '...'
  include { LONG_READ_FILTERING as LONG_READ_FILTERING_FLED   } from '...'
  ```

#### Bug 5: circle_identifier 必填约束误伤长读模式

- **文件**: `nextflow_schema.json`, `workflows/circdna.nf`
- **问题**: schema 中 `circle_identifier` 标记为 required，但长读模式（pacbio/ont）不需要该参数，导致 stub 测试报错 `Missing required parameter: --circle_identifier`
- **修复**:
  - schema 中移除 `circle_identifier` 的 required 约束
  - workflow 中将 circle_identifier 校验逻辑包裹在 `if (params.protocol == "short_read")` 内

### 2. ecc_finder 第四引擎集成

#### 2.1 模块迁移

- **来源**: bio.nf 新建分支构建
- **目标**: `modules/local/ecc_finder/{map_ont,map_sr,asm_ont,asm_sr}/main.nf`
- **容器**: `quay.io/bioinfortools/ecc_finder:1.0.0`（自构建上传至用户 quay.io 频道）

#### 2.2 子流程

- **文件**: `subworkflows/local/eccfinder_pipeline/main.nf`（新建）
- **功能**: 依据 `--eccfinder_mode`（map|asm|both）和 `--protocol`（pacbio/ont）选择子模块
- **输入**: `[val(meta), fastq]`, `[val(meta), genome_fasta]`
- **输出**: `eccdna_candidates`（CSV/FASTA）, `versions`

#### 2.3 主流程集成

- **文件**: `workflows/circdna.nf`
- **变更**: 在长读分支中新增 `run_eccfinder` 判断，调用 `ECCFINDER_PIPELINE`
